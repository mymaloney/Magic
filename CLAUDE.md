# CLAUDE.md

Guidance for Claude Code (and other agents) working in this repository.

## What this repo is

A fork (`mymaloney/Magic`) of **Forge** (upstream: `Card-Forge/forge`), the open-source
Magic: The Gathering rules engine written in Java 17 / Maven. ~59k files, of which ~34k are
card scripts.

**Owner's goal:** build a **Magic: The Gathering adventure game on the Solarus engine** (Lua).
Solarus handles the overworld/RPG side; duels use a **pure-Lua port of Forge's rules**, with the
Java code here as the source of truth for rules behaviour and Forge's card scripts as the card
data (read at runtime, not converted). (An earlier GBA/Butano plan was dropped on 2026-10-30.)
Read these before doing game work:

- `docs/solarus/README.md`: index and **current status checklist**
- `docs/solarus/engine-map.md`: how Forge's engine works, file by file (start here for any rules question)
- `docs/solarus/card-scripts.md`: the card script format and how a script becomes runtime objects
- `docs/solarus/porting-plan.md`: architecture, card pool scope, **decisions log**
- `solarus/README.md`: Solarus setup, running the quest and tests, card sync

Key facts:
- Minimum card pool: `solarus/cardpool/maloney_foundations.txt`; its feature needs are in
  `solarus/cardpool/maloney_foundations_report.md` (regenerate with `solarus/tools/cardpool_report.py`).
- The quest (`solarus/quest/data`) is a **Solarus 2.1** project based on the Solarus starter quest.
  `project_db.dat` and other resource files are maintained by the Solarus Quest Editor; don't
  hand-write them.
- Duels start from map scripts with `require("scripts/menus/duel").start(game, options)` (see
  `solarus/README.md`); the first example is the "duelist" NPC in `maps/first_map`.
- `solarus/quest/data/cards/` is generated by `solarus/tools/sync_cards.py` (pool + `basic_lands.txt`);
  never hand-edit it. Likewise `solarus/quest/data/sprites/cards/` is generated from the owner's
  art in `ART/` by `solarus/tools/sync_art.py`, and `scripts/duel/font_metrics.lua` by
  `solarus/tools/font_metrics.py`.
- Engine progress: `solarus/cardpool/support_report.md` (regenerate with
  `luajit solarus/tools/support_report.lua > solarus/cardpool/support_report.md`); the whole pool
  (335 cards) is supported as of 2026-10-30. When adding an engine feature, also allow it in
  `card_db.lua`'s support check and add a scenario test under `solarus/tests/` (one file per
  feature area, registered in `TEST_FILES` in `run.lua`).
- After engine changes, also run `luajit solarus/tools/stress_games.lua [seed] [games]`:
  AI-vs-AI games with random decks from every card, to catch crashes the scenarios miss.
- Rules engine code lives in `solarus/quest/data/scripts/mtg/`, is **Lua 5.1** (Solarus uses
  LuaJIT), and must **never call `sol.*`**, so it runs headless. Same for the duel screen logic
  in `scripts/duel/`; only `scripts/menus/duel.lua` draws with `sol.*`.
- Tests: `luajit solarus/tests/run.lua` from the repo root. LuaJIT isn't preinstalled in the
  cloud container; `apt-get install -y luajit` works. Solarus itself can't be downloaded here,
  so anything using `sol.*` can't be run in the container. Say so rather than claiming it works.

Unless a task says otherwise, **do not refactor or reformat the Forge Java code**. Keep the
upstream code close to upstream so it stays easy to merge `Card-Forge/forge` master. All game
work goes in the top-level `solarus/` directory, outside the Maven reactor.

## Module map (Maven reactor, root `pom.xml`)

| Module | What it holds | Relevance to the game |
|---|---|---|
| `forge-core` | Static card data: `CardRules`/`CardFace` (parsed scripts), `CardDb`, mana cost parsing, decks, editions, `StaticData` | Card data model, mana cost format |
| `forge-game` | **The rules engine.** `Game`, phases, stack, zones, combat, mana, costs, abilities, triggers, replacements, statics, keywords | **Primary reference** |
| `forge-ai` | Computer opponent (`PlayerControllerAi`, per-effect AI in `forge/ai/ability/*Ai.java`, simulation) | Reference for the duel AI |
| `forge-gui` | Shared, toolkit-neutral GUI logic **and `forge-gui/res/`** (all game data: `cardsfolder/`, `tokenscripts/`, `editions/`, `puzzle/`, …) | Card data source |
| `forge-gui-desktop` | Swing desktop app; **also holds almost all tests** (169 test classes, incl. game simulation tests) | Test harness |
| `forge-gui-mobile`, `-mobile-dev`, `-android`, `-ios` | libGDX mobile front end; Adventure mode lives in `forge-gui-mobile/src/forge/adventure` | Adventure mode is a design reference for the overworld game |
| `forge-lda`, `adventure-editor`, `forge-installer` | Tools | Ignore |

Note: `CONTRIBUTING.md` describes forge-core/forge-game roles slightly loosely; the table
above reflects the actual code (the rules engine is `forge-game`).

## Build & test

Toolchain in the cloud container: `/opt/maven/bin/mvn`, Java 17+.

```bash
mvn -U -B clean -P windows-linux install -DskipTests   # full build (slow, downloads deps)
mvn -B -pl forge-game -am compile                       # just the engine + its deps
mvn -B -pl forge-gui-desktop -am test -Dtest=GameSimulationTest   # one engine test class
```

Tests need a display (CI runs them under `Xvfb :1`, see `.github/workflows/test-build.yaml`).
Engine behaviour tests live under `forge-gui-desktop/src/test/java/forge/ai/simulation/` and
`forge-gui-desktop/src/test/java/forge/gamesimulationtests/`. `SimulationTest.initAndCreateGame()`
plus `addCard(...)` and `PhaseHandler.devModeSet(...)` is the quickest way to set up a board state
and check how Forge resolves something — useful for generating expected results for the Lua tests.

## Fast navigation

- Card script for a card: `forge-gui/res/cardsfolder/<first letter>/<name_lowercase_underscored>.txt`
  (e.g. `l/lightning_bolt.txt`). Tokens: `forge-gui/res/tokenscripts/`.
- Set lists / rarities: `forge-gui/res/editions/<Set Name>.txt`.
- Script effect name → Java class: `forge-game/src/main/java/forge/game/ability/ApiType.java`
  (e.g. `DealDamage` → `effects/DamageDealEffect.java`). Effect AI: `forge-ai/src/main/java/forge/ai/SpellApiToAi.java`.
- Trigger `Mode$` → `forge-game/.../trigger/TriggerType.java`; replacement `Event$` →
  `replacement/ReplacementType.java`; static `Mode$` → `staticability/StaticAbilityMode.java`.
- Keywords (`K:` lines) → `keyword/Keyword.java`, expanded into real abilities in
  `card/CardFactoryUtil.java` (`addTriggerAbility`, `addReplacementEffect`, `addSpellAbility`, `addStaticAbility`).
- Scripting reference docs: `docs/Card-scripting-API/`.

The codebase is large; prefer `Grep` with a path filter over broad reads. `Card.java` (~8k lines),
`CardFactoryUtil.java`, `Player.java`, `GameAction.java` are big — read by method, not whole.

## Conventions

- Follow upstream style; card script conventions are in `docs/Card-scripting-API/Card-scripting-API.md`
  (lowercase filenames, LF endings, minimal default params).
- Upstream `CONTRIBUTING.md` asks AI agents not to add unnecessary tests and to disclose AI authorship in PRs.
- Licensing: Forge is GPL-3.0. Code ported from it (including the Lua engine) is a derivative
  work and must stay GPL-3.0 (Solarus is GPL-3.0 too). Card names/text/art are Wizards of the Coast IP — keep that in mind
  before distributing the game.
