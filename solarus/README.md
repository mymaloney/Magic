# solarus/ — the game

A [Solarus](https://www.solarus-games.org) quest. Design docs and status are in `docs/solarus/`;
this file covers setup and day-to-day workflow.

```
solarus/
  quest/              the Solarus quest: open this folder in Solarus Quest Editor
    data/
      quest.dat       quest properties (Solarus 2.1, title "Arpeggio", save folder)
      project_db.dat  resource list: maps, sprites, sounds… (maintained by the Quest Editor)
      main.lua        entry point (from the Solarus starter quest): runs the menus listed in
                      scripts/menus/initial_menus_config.lua, the last one starts the game
      cards/          Forge scripts for the card pool + pool.lua  [generated by tools/sync_cards.py]
      scripts/mtg/    rules engine, pure Lua, no sol.* calls (module table in docs/solarus/porting-plan.md)
        controllers/  ai.lua (computer opponent), prompt.lua (human player via the duel menu)
      scripts/duel/   duel_ui.lua (duel screen logic: cursor, selections, prompts; no sol.*),
                      decks.lua (preconstructed decks of supported cards)
      scripts/menus/  duel.lua (duel launcher + drawing: duel.start(game, options)) + starter menus
                      (logo, dialog box, start_game)
      maps/first_map  the starting room, with the "duelist" NPC (first_map.lua starts her duel)
      languages/en/text/dialogs.dat   dialog text (duelist.*)
      maps/ sprites/ tilesets/ sounds/ musics/ enemies/ items/ fonts/ …   starter quest content
  cardpool/           card lists (+ basic_lands.txt) and generated reports
                        maloney_foundations_report.md  features the pool needs
                        support_report.md              which cards the engine runs today
  tools/              cardpool_report.py, sync_cards.py, support_report.lua
  tests/              run.lua + test_*.lua: headless tests (parser, mana, rules scenarios, full AI
                      games, duel screen logic driven by key presses)
```

The quest is built on the **Solarus 2.1 starter quest** (created with the Quest Editor), which
supplies the overworld, hero, HUD, dialog box and assets. Startup flow: Solarus logo →
`start_game` (loads `save1.dat`, `first_map`).

In `first_map`, talk to the woman in the middle of the room (face her, press the action key). She
asks "Fancy a game of Magic?"; answer yes to duel her: you play the Rakdos deck against her Green
AI deck. The game is suspended during the duel; afterwards she comments on the result and a win
adds 1 to the savegame value `duelist_wins`.

To start a duel from any other script:

```lua
local duel = require("scripts/menus/duel")
local decks = require("scripts/duel/decks")
duel.start(game, {
  player_deck = decks.rakdos, opponent_deck = decks.green, opponent_name = "Duelist",
  on_finished = function(result) end,  -- "won", "lost" or "draw"
})
```

### Duel controls

| Key | Does |
|---|---|
| Arrows | Move the cursor: opponent's permanents / your permanents / your hand |
| Space | Play or cast the focused card (green = playable); pick attackers; pick a blocker, then the attacker it blocks; pick cards to discard; pick a target; say yes to a "may" ability |
| Return | Pass priority / confirm attackers, blocks, discards, targets / leave the result screen |
| Backspace | Cancel a half-made block; say no to a "may" ability |
| Escape | Quit (handled by `main.lua`) |

Screen: opponent's status and lands, their permanents, the current situation, the last log
line, your permanents, lands and hand, your status, then a panel with the focused card's
details (or the recent log) and the key help. Box colours: green playable, red attacking or
picked, blue blocking, purple blocker being placed, dark tapped; yellow frame = cursor.
Lands are summarized as "Forest 3/5" (untapped/total) since mana is paid automatically.

While you choose targets, the hand row shows the candidates instead (players appear as "You" /
"Opp" boxes with their life).

The game stops only when you have a real choice: steps where you can't do anything pass on
their own, and combat damage is divided automatically. If all you could do is cast an instant,
it only stops in your main phases, when something is on the stack, after blockers are declared,
and at the opponent's end step. The AI acts instantly; follow what it
did in the log. `duel_ui.lua` is covered by headless tests; the drawing code in `duel.lua` was
confirmed on Solarus 2.1 by the owner (2026-10-30). Note any display fixes here.

The NPC (`npc{}` entry in `maps/first_map.dat`) and `dialogs.dat` were written by hand in the
cloud session in the editor's file format; the NPC flow was only run against a stubbed `sol`
API. Opening the map in the Quest Editor should show her; if the editor rewrites those files,
commit its version.

## Setup

1. Install **Solarus 2.1** (engine + **Solarus Quest Editor**; the Solarus Launcher bundles both)
   from solarus-games.org. `quest.dat` declares `solarus_version = "2.1"`.
2. **Python 3** for the tools; **LuaJIT** (or any Lua 5.1) to run the tests outside Solarus.

## Run

```bash
solarus-run solarus/quest                      # or open solarus/quest in the Quest Editor and press Run
luajit solarus/tests/run.lua                   # headless tests, from the repo root
```

## Card pool

```bash
# after editing solarus/cardpool/maloney_foundations.txt or merging upstream Forge:
python3 solarus/tools/sync_cards.py   solarus/cardpool/maloney_foundations.txt solarus/cardpool/basic_lands.txt
python3 solarus/tools/cardpool_report.py solarus/cardpool/maloney_foundations.txt \
        -o solarus/cardpool/maloney_foundations_report.md
luajit solarus/tests/run.lua

# after engine changes:
luajit solarus/tools/support_report.lua > solarus/cardpool/support_report.md
```

Don't hand-edit files in `quest/data/cards/`. To change a card's behaviour, fix the script in
`forge-gui/res/cardsfolder/` (ideally upstream) and re-sync.

## Adding content

Use the **Quest Editor** for maps, tilesets, sprites and their animations, sounds, music, and
dialogs. It keeps `project_db.dat` in sync, so don't hand-write that file (the first,
hand-written version of this quest, with an empty `project_db.dat`, wasn't recognized by the
editor). Sprites are PNG sheets plus a `.dat` file describing
animations and directions, all edited visually. Commit the editor's output files as-is.

Lua conventions:
- Modules return a table; load them with `require("scripts/…")` (paths relative to `data/`).
- Lua 5.1 only (Solarus runs LuaJIT).
- Anything under `scripts/mtg/` must stay free of `sol.*` so `tests/run.lua` can load it.
